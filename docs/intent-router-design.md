# Intent Router 设计理念（人话版）

## 一句话结论

**只读实体加 `intent_router` 标签就能查；会改变设备状态的操作，必须先定义受审查的能力。**

这条规则解决两个问题：

- 新增温度、猫砂重量、电池、水位等只读实体时，不应该每次都改 Router 代码。
- “开门、启动设备、改温度”等操作不能因为打了一个标签，就自动获得执行权限。

## 标签到底代表什么

给 HA 实体添加 `intent_router` 标签，表示：

> 我明确允许 Intent Router 看到并使用这个实体。

它不代表：

- 自动公开给 HA Assist；
- 自动公开给 Siri；
- 自动允许控制设备；
- 允许 AI 自己拼 HA service 或 `entity_id`。

这些入口和权限彼此独立。Router 只处理带标签的实体，HA 仍是状态与执行的唯一权威。

## 只读实体：标签就是接入配置

默认支持以下只读域：

- `sensor`
- `binary_sensor`
- `event`

Router 同步 HA 后会按以下顺序处理：

1. 有专用模板时，优先使用模板。例如温度仍映射成 `sensor.read`，可获得单位、指标和新鲜度等专用语义。
2. 没有专用模板时，自动生成通用 `entity.read` 能力。
3. 通用能力按**实体**区分，而不是按设备区分。猫砂重量、猫砂不足和设备状态即使属于同一个猫砂盆，也不会互相覆盖。

因此，给这些 Petkit 实体加标签后，不需要为每一项编写代码：

| 设备 | 已允许的只读信息 |
|---|---|
| 猫砂盆智能净味器 | 错误、电池、净化液不足、水位 |
| 小佩智能全自动猫厕所 MAX2 | 猫砂等级、猫砂缺少、猫砂重量、设备状态、最近事件 |

用户可以问“猫砂重量还有多少”“净化液是不是不足”“猫厕所最近有什么事件”。Router 根据 HA 中的设备名、实体名、别名和区域匹配具体实体，再从 HA 读取当前状态。

真实 HA `entity_id` 只保留在 Router 内存中，不进入 LLM、公共能力目录或 Git。

## 为什么还保留模板

通用读取解决的是“能安全地读出一个实体当前是什么”。模板解决更丰富、更严格的语义，例如：

- 把温度、湿度、PM2.5 统一成专用指标；
- 为某类传感器定义允许的新鲜度；
- 把厂商原始值翻译成稳定枚举；
- 汇总同一设备的多个实体；
- 为控制动作定义确认、成功条件和失败响应。

所以模板是增强能力，不是所有只读实体的入场券。

## 诊断实体怎么处理

`diagnostic` 类实体默认排除，避免批量暴露内部信号。但如果某个安全只读实体被**明确添加** `intent_router` 标签，并且配置允许 `diagnostic` 只读回退，它可以进入目录。例如电池电量。

`config` 类实体始终不能通过通用读取进入目录，因为它通常代表配置或控制面，而不是普通状态。

## 可写能力：标签不等于授权

`switch`、`button`、`number`、门锁、空调控制和设备动作等不会自动生成可写能力。新增可写能力仍必须具备：

- 稳定逻辑意图；
- 风险等级；
- 允许来源；
- HA 动作白名单或稳定 HA 脚本；
- 成功条件；
- 失败响应；
- 必要时的确认策略。

AI 只能从已经生成的逻辑能力中选择，不能生成 HA service 或实体 ID 直接执行。

霍曼猫粮机是一个具体例子：标签本身不会开放任意 `button`。Router 另有一个经过审查的窄模板，只匹配名称明确表示“手动出粮 1 份”的按钮，将动作固定为 `button.press`，不接受份数参数，并要求每次确认。新增其他按钮即使加了标签，也不会自动获得控制权限。

## 什么情况下需要改代码或配置

| 变化 | 是否要改 Router |
|---|---|
| 新增一个只读 `sensor` / `binary_sensor` / `event`，并加标签 | 不需要 |
| 同类设备换了品牌或型号，仍暴露普通只读实体 | 不需要 |
| 想让某个字段更容易理解，或增加口语别名 | 通常只改 HA 名称/别名 |
| 需要多实体汇总，例如“猫砂盆整体怎么样” | 需要新增聚合模板或 Agent 能力 |
| 新增一种控制动作 | 需要新增受审查的可写能力 |
| 让 AI 自由探索、连续查询并组合答案 | 属于未来 Agent/ReAct 层，不属于当前单轮 Intent Router |

## 当前边界

当前 Router 是单轮意图识别与安全执行层，不是通用家庭 Agent。它擅长：

- 明确读取一个状态；
- 明确执行一个已授权动作；
- 对模糊目标进行追问。

“把两个猫砂盆的状态都查一遍，再综合判断耗材是否需要补充”需要多步调用和结果组合，后续可以在 Router 之上增加 Agent/ReAct 层。即使增加 Agent，最终读取和执行仍只能经过本 Router 暴露的安全能力。

## 数据流

```text
自然语言
  → 本地别名/规则匹配（明确命中时不调用 LLM）
  → 必要时由 LLM 从脱敏能力目录中选择 intent + target
  → JSON Schema 校验
  → 权限与风险策略校验
  → 从内存映射找到真实 HA 实体
  → Home Assistant 读取状态或执行动作
  → 返回人能看懂的结果
```

`contracts/intent.schema.json` 约束的是模型能返回哪些标准意图和参数；HA 中当前有哪些实体，则由运行时自动发现决定。两者职责不同，不应该为每个新实体修改 Schema。
