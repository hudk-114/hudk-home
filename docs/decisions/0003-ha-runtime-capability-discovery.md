# ADR-0003：普通设备能力以 HA 运行时发现为准

- 状态：接受
- 日期：2026-08-18

## 决策

灯、标准传感器、扫地机、空调和场景等已有安全模板的普通设备实例，以 Home Assistant 运行时目录为准。Router 从经过 `intent_router` 标签筛选的实体中读取状态、设备、区域和动作信息，生成只存在内存中的能力映射。

`config/capabilities.yaml` 只保留以下内容：

- 必须经过稳定 HA 脚本的核心动作；
- 不对应普通设备实例的系统能力；
- 需要人工固定名称、风险策略或兼容层的特殊能力。

实体没有独立区域时继承设备区域。真实 HA `entity_id` 不进入公共目录、LLM 提示或 Git。已经发现同类真实能力时，带 `REPLACE_WITH` 的静态占位能力不向调用方和 LLM 公开。

## 原因

- 新增同类型设备只需在 HA 中配置名称、区域和标签，不需要同步修改仓库。
- 避免静态占位设备与真实设备同时出现，造成目标歧义。
- HA 继续作为设备状态、设备注册表和区域关联的唯一权威。
- 特殊能力仍可通过稳定脚本与版本化策略接受审查。

## 代价

- Router 重启后需要重新连接 HA 才能恢复动态目录。
- HA 区域、名称和标签质量会直接影响自然语言解析。
- 新设备类型仍需新增安全模板、测试、成功标准和失败响应。
